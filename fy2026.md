### Enterprise CI/CD Service Reliability and Security Gate Adoption

Operate and improve enterprise CI/CD services and reusable delivery patterns (e.g., GitHub Actions reusable workflows, runner fleet, templates), achieving defined reliability targets while expanding adoption of standardized required security gates across CISA repositories and teams.

#### Achieved Expectations

**Standard:** To earn *Achieved Expectations*, all items below must be met.

1. **Availability:** Maintain **at least 97.0% monthly availability** for CI/CD components under employee control.

   * **Availability formula:**

     `availability = (total_minutes_in_month - outage_minutes) / total_minutes_in_month`

   * **Outage minute definition:** any minute in which **at least 25%** of runners in the supported pool are **unavailable** (offline/unreachable) **and** the condition persists for **at least 10 consecutive minutes**.

   * **Exclusions:** vendor/SaaS/platform incidents outside employee control, documented via vendor status page and internal incident note.

2. **Incident records:** For **100%** of Priority 1 CI/CD incidents attributable to CISA-owned components, publish an incident record within **5 business days** that includes:

   * timeline
   * root cause
   * corrective actions
   * dated completion status for each action item

3. **Required security gates adoption:** Implement a standard reusable **Secure PR Gate** workflow and configure it as a **required status check** in **at least 8 repositories**, including **at least 3 repositories** owned outside the employee’s direct team.

   * Gate must include, at minimum: **SAST (or equivalent), dependency vulnerability scan, and secret scanning**.
   * Gate must run on PRs targeting the default branch.

4. **Default-branch reliability:** Achieve **at least 90% green default-branch runs** for the standardized CI workflow across the repos onboarded in item (3), measured monthly from workflow runs.

   * `green_rate = successful_runs / total_runs`
   * Exclude canceled runs and runs failing solely due to an upstream platform incident ID.

#### Exceeded Expectations

**Standard:** To earn *Exceeded Expectations*, all items below must be met **and** all Achieved Expectations items must be met.

* Availability **at least 98.0% monthly**.
* Onboard **at least 10 repositories** total to required checks, including **at least 4** outside the employee’s direct team.
* Add SBOM generation to the standardized pipeline for **at least 4** onboarded repos, evidenced by stored artifacts and build logs.

#### Achieved Excellence

**Standard:** To earn *Achieved Excellence*, all items below must be met **and** all Achieved Expectations items must be met.

* Availability **at least 98.5% monthly**.
* Onboard **at least 12 repositories** total to required checks, including **at least 5** outside the employee’s direct team.
* Add **SBOM generation and artifact provenance attestation (or equivalent verifiable supply-chain output)** to the standardized pipeline for **at least 6** onboarded repos, evidenced by stored artifacts and build logs.

### Secure Development Tooling Governance: Compliance, Patch Cadence, and Measurable Risk Reduction

Establish and enforce a measurable governance baseline for secure software development tooling and repository posture, with a documented patch cadence for shared components and an auditable compliance record.

#### Achieved Expectations

**Standard:** To earn *Achieved Expectations*, all items below must be met.

1. **Published baseline:** By **2026-04-15**, publish a **versioned** “Secure Repo & Tooling Baseline” that includes a checklist of required controls.

   * Evidence: baseline document in an official repository with version tag/release date.

2. **Quarterly audit reports:** Deliver **2 audit reports** by **2026-06-30** and **2026-09-30**, each containing:

   * exact repository inventory assessed (explicit list)
   * each baseline control marked **PASS/FAIL/NOT-APPLICABLE** with objective evidence
   * dated remediation plan for each FAIL item

3. **Measured compliance improvement:** For a fixed set of **at least 15 repositories** (listed in the baseline release), achieve:

   * **at least 85% control-pass rate** by **2026-06-30**

   * **at least 92% control-pass rate** by **2026-09-30**

   * Pass rate computed as:

     `pass_rate = passed_controls / (passed_controls + failed_controls)`

     (exclude N/A)

4. **Patch cadence:** Complete **at least 6** documented tooling/security maintenance updates by **2026-09-30**, each consisting of:

   * PR (or change record) upgrading a shared workflow/action/base image/runner image/centrally maintained tool configuration, and
   * a release note entry stating what changed and why (CVE/reference if applicable)

#### Exceeded Expectations

**Standard:** To earn *Exceeded Expectations*, all items below must be met **and** all Achieved Expectations items must be met.

* Publish baseline by **2026-04-01**.
* Expand fixed repo set to **at least 20 repositories** and reach **at least 94% pass rate** by **2026-09-30**.
* Complete **at least 8** documented tooling/security maintenance updates by **2026-09-30**.

#### Achieved Excellence

**Standard:** To earn *Achieved Excellence*, all items below must be met **and** all Achieved Expectations items must be met.

* Publish baseline v1 by **2026-04-01** and baseline v2 by **2026-08-31** (v2 reflects audit results and updates controls).
* Expand fixed repo set to **at least 25 repositories** and reach **at least 95% pass rate** by **2026-09-30**.
* Deliver **2 knowledge-sharing sessions** by **2026-08-15** with recording, slides, and attendance list.

### Self-Service Development Tool Provisioning via Infrastructure as Code

Deliver a self-service, PR-driven provisioning capability for common development tools using modular Infrastructure as Code (IaC), with measured provisioning time and documented operator runbooks.

#### Achieved Expectations

**Standard:** To earn *Achieved Expectations*, all items below must be met.

1. **Modular IaC deliverables:** By **2026-07-31**, deliver **at least 3 reusable IaC modules** for common development tools.

   * Each module must include: inputs, outputs, validation, and README usage instructions.
   * Evidence: module repositories/paths with version tags/releases.

2. **Self-service workflow:** By **2026-08-31**, implement a PR-based request path (GitOps repo + CI validation + approval + automated apply) enabling tenant teams to request one of the modules via a standard template.

   * Evidence: request template + CI check runs + apply/deploy logs.

3. **Provisioning time metric:** For **at least 10 completed provisioning requests** between **2026-09-01** and **2026-09-30**, achieve **at least 80%** completed in **no more than 1 business day**, measured from:

   * **start:** PR merge timestamp
   * **end:** “ready for use” timestamp recorded in deployment logs (same definition for all requests)

4. **Operational readiness:** By **2026-08-31**, publish operator runbooks for the self-service system, including rollback steps, break-glass procedure, and escalation path.

#### Exceeded Expectations

**Standard:** To earn *Exceeded Expectations*, all items below must be met **and** all Achieved Expectations items must be met.

* Increase module count to **at least 4** by **2026-08-15**.
* For **at least 12 requests** in the 2026-09-01 to 2026-09-30 window, achieve **at least 80%** in **no more than 8 business hours**.
* Deliver **1** adoption session for tenant teams by **2026-09-15** with recording, materials, and attendance list.

#### Achieved Excellence

**Standard:** To earn *Achieved Excellence*, all items below must be met **and** all Achieved Expectations items must be met.

* For **at least 16 requests** in the 2026-09-01 to 2026-09-30 window, achieve **at least 80%** in **no more than 4 business hours**.
* Deliver **2** adoption sessions for tenant teams by **2026-09-15** with recording, materials, and attendance list.
